# Mesting Music 1.0.11：酷狗与网易云双平台

本版基于 1.0.10，用户确认版本为 **1.0.11 / Android code 32**。欢迎页先显示“酷狗登录”，再显示“网易云登录”，游客入口保留。选择平台后，使用现有页面框架展示对应的登录方法。酷狗提供手机号、酷狗扫码、微信扫码和 QQ 扫码；网易云提供网易云扫码、手机验证码、手机密码和邮箱密码。

用户明确要求沿用酷狗现有页面、控件、底部胶囊播放器、交互与过渡效果。本版复用这些组件，只调整登录导航、平台文字和数据来源，没有替换现有玻璃、播放页、MV 页或动效实现。

## 账号与播放状态

- “我的”新增同款玻璃按钮“切换音乐平台”。两边都登录过后，直接切换，并分别保留登录状态。
- 切换前暂停并保存离开账号的当前歌曲、队列和播放位置；进入目标平台后恢复该账号自己的记录，保持暂停，等待用户手动继续。
- 账号标识包含平台和用户 ID，避免两个平台恰好使用相同数字 ID 时串库。酷狗原有 `kugou:<id>` 存储范围保持兼容，网易云使用 `netease:<id>`。
- 明确退出登录只删除当前平台凭据，保留该账号播放快照与另一平台登录状态。再次登录同一账号后可以恢复。
- 网易云 Cookie 单独保存在安全存储中，公共会话只暴露不可逆的凭据摘要。酷狗传输和听歌同步不能收到网易云 Cookie 或账号对象。
- 账号切换后，旧请求不能回写新账号状态；旧仓库的写入在发送前核对凭据，搜索防抖、排行榜缓存和搜索历史按平台及账号隔离。

## 数据适配与接续入口

`lib/features/music_platform/netease/` 放置网易云协议、登录、安全存储与业务适配器。协议参考用户指定的 YesPlayMusic 所使用的网易云接口体系，具体原生端口固定于 `@neteaseapireborn/api` 4.29.7 的 eapi/weapi 行为。MIT LICENSE 与移植说明在 `third_party/netease_protocol/`，同时随 APK 离线打包，并通过现有许可证列表提供阅读。应用直接使用 HTTPS，不要求在用户手机启动 Node 服务，也未加入音源解锁逻辑。

`platform_backend_providers.dart` 集中选择平台。搜索、推荐、歌单、歌词、音质、评论、MV 和资料适配器把网易云响应转换成现有模型，再进入原页面。`CloudLibraryRepository` 抽取两个云端歌单仓库的共同边界，使同一歌单界面能处理平台对应的管理权限和评论资源。歌曲与歌单 ID 均包含来源标识，其他平台资源不能误写入当前云端账号。

头像使用网易云 NOS 分配、上传、提交的既定流程；音乐账号 Cookie 不发送到 NOS 上传主机。网络请求有超时，带账号凭据的请求不跟随重定向，写操作没有自动盲重试。音质按接口实际返回的可用资源展示，版权或会员限制按返回结果处理。

`PlatformAccountController` 串行提交登录、切换与退出，通过注入的播放准备回调与播放器解耦；应用仍只有原来的一个音频处理器。`PlaybackPersistenceController` 保存与恢复各账号快照。切换已有账号或首次添加第二平台时，不重新播放欢迎页和新手流程。

酷狗专有的一起听、听书、奖励与官版听歌统计仍按原酷狗协议运行。网易云账号不会进入酷狗统计任务；本地播放记录继续按当前账号记录，不把本地数据标作官方累计分钟数。

## 验证

- 17 个相关测试文件一次运行 **150 项通过**，覆盖登录入口、双账号存储、重启恢复、退出范围、同 ID 隔离、真实播放器与 SQLite 队列位置恢复、旧响应拒绝、二维码私有会话、云端权限、头像、评论、MV、歌词、音质及原有回归。
- AES/RSA 固定测试向量由独立 Node 标准加密实现生成，Dart 协议对照通过。
- 静态分析无问题。修正测试文件的提示后，6 项数据适配测试再次通过。
- 10 项界面测试覆盖浅色、深色、320×650 小屏和大字体；已查看登录与账号页面截图。用于主机截图的字体仅在测试开关下加载，没有进入发布资源。
- 使用真实公开接口只验证了匿名二维码生成和搜索；未发送短信、未使用真实账号执行云端写入。真实账号登录、版权播放、覆盖安装与手机交互由用户安装验收。

发布包继续使用 `com.mesting.music.beta`、原证书和 ARM32/ARM64 双架构。共享 `pubspec.yaml` 的旧 stable 版本不决定本次公开身份；发布入口明确传入 1.0.11 / 32，随包六条更新说明与内置版本历史同步。发布与产物摘要以本版接续及核验文件为准。
