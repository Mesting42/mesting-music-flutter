# Beta.18 interface refinements

Confirmed on 2026-10-26, based on Beta.17 `e8ac5bb23ff51787b3a881ad252b4fa9bed97677`.
The later confirmed success-card reference supersedes the initial 214dp preview:
**104 by 104dp**, rounded square, upper center below the guide header.

## User-visible behavior

- The cold-start greeting uses lightweight greeting/name typography without a
  capsule or music-note badge. The one-cold-process, five-visible-second rule
  remains; long names truncate without forcing the home title onto two lines.
- Playback destination uses an audio-broadcast contour for local output and
  paired earphones for headphones. Dialog speakers/checks share authored vector
  contours. The dialog-only volume slider keeps framework semantics, keyboard
  control and the existing native media-volume controller.
- More/close icons retain their hit targets and the small circled X, with
  scale/opacity feedback instead of the large pressed circle. Keyboard focus
  remains visible. The classic turntable keeps its intentional contrast base.
- Successful quality catalogs remain in memory for up to 64 recordings. Existing
  account-future dependencies invalidate on identity/token replacement; failures
  are not retained. No disk cache or permission bypass is introduced. Loading
  height changes smoothly; result contents fade/translate inside the glass.
- Initial comment/resource loading has a bare activity indicator. Stable comment
  keys retain completed entrance state while appended comments reveal; existing
  order/filter/account guards and write-result handling remain authoritative.
- Blue glass buttons cancel their press on scrolling gesture cancellation.
  Their ambient lift/specular is blue-tinted and bounded, retaining premium
  optics while preventing a white press wash from hiding a white label.
- The guide mounts visibly and interactively in the same frame as login success.
  The small non-blocking HUD paints only its own square. Next/Skip and Back keep
  the same guide state; a delayed dismissal cannot reset progress or reopen it
  after finishing. Duplicate auth events stay silent, and the original one-shot
  chime remains separate from the music owner.

## Implementation boundaries

`beta_content_reveal.dart` owns foreground motion, not glass compositing.
`beta_icon_button.dart` retains framework input/focus behavior. Audio glyphs and
the dialog volume presentation are separate from route and volume controllers.
The quality provider retains successful states with bounded release callbacks.
The entry coordinator owns guide state; the success HUD owns only timed feedback.

The Apple reference is [playback destination behavior](https://support.apple.com/en-kg/guide/beats/devbb3350239/web)
and [SF Symbols](https://developer.apple.com/sf-symbols/). The application vectors
are authored code, not exported Apple assets, and do not infer an AirPods brand
from a generic headphone route.

## Validation and delivery

The final Beta-flavor regression run passes all 275 tests; analysis reports no
issues. The normal suite has 724 passes, 89 skips and three existing failures:
multiline editing-menu gap, the queue's rose-color guard, and the follower-removal
sheet above the persistent player. Each was reproduced against the pristine
Beta.17 commit before classifying it as baseline behavior. Do not describe that
normal suite as fully passing. The independent finish review found no new
material defect in this request's source and supplied final renders.

The external handoff contains the current logs, baseline comparison, 24 final
rendered previews and a source archive. No phone is connected: software rendering
cannot certify Android GPU output, haptic hardware, real login/SMS, device
switching or physical installation/data retention.

The user supplied the existing Beta.17 signing key locally. The delivered Release
APK uses package `com.mesting.music.beta`, version `1.0.37-beta.18`, code `18`,
and both `armeabi-v7a` and `arm64-v8a`. Its certificate matches Beta.17, satisfying
Android's package/signer/version prerequisites for upgrading that delivered
installation. APK v2 signature, ZIP 16 KiB alignment, ARM64 ELF segment alignment
and every packaged native library against its build output were verified.
Re-signing the delivery copy changed no compiled payload; the machine's global
debug key was not replaced. See `release/Mesting-Music-v1.0.37-beta.18-verification.json`
for exact hashes and the verification boundary. Private keys remain outside Git
and source archives. No commit, push, Release publication or phone installation
was performed by this delivery.
